#deck:Ambientes de software
O que é o ambiente de Desenvolvimento?	Onde a pessoa desenvolvedora escreve, modifica e testa o código na própria máquina, de forma isolada. Objetivo: criar funcionalidades e corrigir erros. Testes comuns: unitários e de integração.
O que é o ambiente de Teste?	Executa testes manuais ou automatizados para identificar falhas, problemas de segurança e erros de funcionamento. Tem infraestrutura semelhante à de produção, geralmente com dados fictícios.
O que é a Homologação (Staging)?	Etapa de validação mais próxima do produto final. O cliente ou um grupo restrito de usuários verifica se o sistema atende aos requisitos antes da publicação. Pode incluir testes de aceitação, migração de dados e configurações finais.
O que é o ambiente de Produção?	Ambiente em que o sistema fica disponível para os usuários finais, em funcionamento real. Permite receber feedback e identificar melhorias.
Qual o fluxo tradicional dos ambientes?	Desenvolvimento (criação do código) → Teste (identificação de falhas) → Homologação (validação do cliente) → Produção (disponibilização aos usuários). Algumas empresas usam menos ambientes, especialmente em metodologias ágeis.
O que é Deploy e qual a diferença principal entre Blue-Green e Canary?	Deploy é o processo de disponibilizar uma versão do software em um ambiente. Blue-Green trabalha com dois ambientes/versões para facilitar a troca; Canary libera a atualização gradualmente para parte dos usuários.
O que é Blue-Green Deployment?	Mantém duas versões do ambiente. Enquanto uma funciona normalmente, a outra recebe as alterações. Após a validação, o tráfego é direcionado para a nova versão, reduzindo o tempo de indisponibilidade.
O que é Canary Deployment?	Libera a nova versão inicialmente para uma pequena parcela dos usuários. Se os resultados forem satisfatórios, a atualização é ampliada gradualmente.
O que é Integração Contínua (CI) e quais suas vantagens?	Integrar frequentemente o código e executar verificações, principalmente testes automatizados. Vantagens: bugs identificados cedo, menos retrabalho, mais qualidade e segurança, mais produtividade, entregas mais rápidas e menor custo.
Para que servem as variáveis de ambiente e o Dotenv?	Separam configurações e credenciais (senhas de banco, chaves de API) do código, evitando falhas de configuração e vazamentos. O Dotenv facilita o carregamento dessas variáveis em aplicações Node.js.
